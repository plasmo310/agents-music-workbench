# 生成物と検証の詳細

## 工程（python python/cli.py project build）

| 工程 | ログ | 内容 |
|---|---|---|
| 1 パイロット | `logs/pilot.log` | 先頭1曲 × 全音源。新規タブで作成→保存→開き直し→音源・音色・ノート数を照合→レンダー（preview.wav） |
| 2 残り | `logs/remaining.log` | 残りの曲を同様に |
| 3 音量合わせ | `logs/level_match.log` | preview.wav の RMS/ピークからマスター音量を決め、保存→開き直し→ preview_matched.wav |
| 4 全曲まとめ | `logs/overview.log` | 各曲の .rpp をサブプロジェクトとして並べた `<ジョブ>_overview.rpp`。開き直して参照先を照合 |
| 5 納品情報 | `delivery.json` `README.md` | 共通MIDIの往復一致、試聴WAVの無音・クリップ・長さ。カタログ更新 |

## プロジェクトの構成

- ループ曲：MIDIアイテムを3周並べ、中央の1周を再生・ループ・レンダー範囲にする（前後の周は余韻の確認用）。3周は独立したアイテムなので、編集は中央の周で行い、必要ならコピーする。
- SE：テンポ未定義なら120 BPMの作業グリッド。0.35秒の余韻枠つき。
- `=START` / `=END` マーカー：サブプロジェクトとして読み込まれたときに使う範囲（中央の1周／SE＋余韻）。
- ゲート：音源のリリースと二重にならないよう、RPP内のMIDIは打楽器10 ms／その他25 ms 短縮（プロファイルで変更可）。共通MIDI `score.mid` は元の長さ。
- 試聴WAV：48 kHz / 24-bit / ステレオ。`preview.wav` は音量合わせ前の検査用。

## 注意

- 単体の MIDI は音色を保持しない。音色込みで開く入口は `.rpp`。
- 全曲まとめのプロキシ（`.rpp-PROX`）は各曲フォルダに作られる。曲を編集して保存すると REAPER が作り直す。
- REAPER の設定「読み込んだメディアをプロジェクトフォルダにコピー」が有効でも、全曲まとめは曲の .rpp を直接参照する（複製しない）。
