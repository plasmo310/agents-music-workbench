# プロジェクト生成リストからREAPERプロジェクトを作る

選択済みの曲だけを、編集可能なMIDIと音源の音色設定を保持した REAPER プロジェクトにする。
この工程は判断を含まない決まった処理で、利用者はルートの `generate-projects.bat`（macOS / Linux は `generate-projects.sh`）で自分でも実行できる。エージェントは実行・失敗時の原因調査・音源プロファイルの調整を担う。
元のプレビューWAVの完全再現ではなく、音符・リズム・構成を引き継いだ **音源別のアレンジ** として扱う。

## 手順

1. **リストを確認する**：`python python/cli.py project-list`
   - 最新のリスト（`data/project-lists/*.json` と ダウンロードフォルダの `project-list-*.json` のうち最も新しいもの）の曲一覧が出る。利用者が別のファイルを指定したら `--file` を使う。
   - リストが見つからない・曲が存在しない場合はエラーになる。**別の曲で代用したり全曲を対象にしたりしない**。試聴カタログ（`data/library/index.html`）で★を付けて「プロジェクト生成リストを保存」を押すよう案内する。
2. **環境を確認する**：`python python/cli.py doctor`
   - REAPER の場所と、音源プロファイルのプラグインが REAPER に登録されているかを表示する。登録は実ロードやライセンス認証の証明ではない。
   - 使う音源は `project-list` の表示に出る（優先順：コマンドの `--profiles` ＞ リストで選んだ音源 ＞ `config.json` ＞ 既定の `reasynth`）。利用者が会話で音源を指定したら `--profiles` で渡す。
   - 選ばれた音源のプラグインが `doctor` で「登録なし」なら、生成前に利用者へ伝える。MASSIVE X など別製品や別の音源で勝手に代用しない。
3. **生成する**：`python python/cli.py project all [--profiles ...] [--name 短い名前]`
   - `data/projects/<日時-名前>/` に準備 → REAPER で制作。REAPER が起動していればそのウィンドウに新しいタブを開いて作業し、終わると閉じる。**利用者が開いているプロジェクトには触れない**。
   - 最初に先頭1曲だけ全音源で制作し（パイロット）、保存・再読み込み・レンダーが成立してから残りへ進む。
   - 利用者が「まず1曲で音色を確認したい」と言った場合は `project all --stage pilot` で止め、確認後に `project build <ジョブID>` で続ける（制作済みの曲は飛ばされる）。
4. **結果を報告する**：`data/projects/<ジョブ>/README.md` と `delivery.json` を読み、次を簡潔に伝える。
   - 全曲まとめ `<ジョブ>_overview.rpp`（各曲がサブプロジェクトとして並ぶ。曲ごとにトラックが分かれ（音源を複数選んだ場合は、曲のフォルダの中に音源ごとのトラック）、時間方向に全曲が順に並ぶ。ダブルクリックで各曲を編集）
   - 1曲ずつの編集用 `.rpp`、共通MIDI `score.mid`、試聴WAV `preview_matched.wav`
   - 試聴カタログの「生成済みプロジェクト」タブで聴き比べ・パスのコピーができること
   - `verification.warnings`（例：ベンド幅を設定できない音源）と、聴取評価は未実施であること

## 失敗したとき

- `logs/*.log` に REAPER 側のログがある。`ERROR` の内容をそのまま利用者に伝える。
- **プラグインを読み込めない**：インストール・REAPER のプラグインスキャン・ライセンス認証を確認するよう案内する。別の音源で勝手に代用しない。
- **タイムアウト**：REAPER にダイアログ（ライセンス、保存確認、レンダー警告など）が出ていないか利用者に確認してもらう。ダイアログを勝手に操作しない。
- **パラメーター・選択肢が見つからない**：音源のバージョン違いの可能性。[references/profiles.md](references/profiles.md) を読み、REAPER 上で実際の名前・値域を確認してからプロファイルを直す。パラメーター番号や値を推測で書かない。
- 失敗した作業タブは `logs/<工程>_failed.rpp` に保存されて閉じる（変更が残る場合は開いたまま）。
- 直したら `python python/cli.py project build <ジョブID>` で再開できる（`--force` で制作済みも作り直す）。

## 完了条件

- 選択した曲だけが対象で、共通MIDIの音符が元の音符データと一致している（delivery の検証）。
- 各 `.rpp` を開き直して音源がロードされ、音色設定とMIDIが残り、レンダーできた（ログの RELOADED / RENDERED / MATCHED）。
- 全曲まとめのサブプロジェクト参照が各曲の `.rpp` を指している（ログの OVERVIEW）。
- 試聴WAVに無音・クリップ・長さの異常がない。数値検査は音楽的品質の保証ではない。聴いていなければ「未試聴」と明記する。
- 未検証の項目があれば完了扱いにしない。

詳細は [references/verification.md](references/verification.md)。
